# Agent instructions

## Waymark design work

When grilling, domain-modeling, or otherwise clarifying Waymark behavior, record every settled feature decision in the Waymark design map (`.clove/issues/waym-VS5Z5543.md`) as soon as it is resolved. Do not defer, batch, or compress settled decisions into a few vague summary bullets: capture the concrete rules, constraints, exceptions, and examples needed to guide the functional specification and implementation tickets. Keep unresolved questions in the unresolved section; update the map inline after each confirmed round, before asking the next round. Do not update the functional spec or implementation tickets until the user asks for that synchronization or confirms the design is ready. After completing requested file changes, commit them; inspect the staged diff and use a concise commit message that describes the change.
