Resolution: the error taxonomy is frozen as follows.

**One registry, one classification.** Every business code lives in one shared registry carrying its exit class, retryability, typed details shape, location kinds, and whether it may also appear as a diagnostic finding. The CLI exit mapping and the MCP business-error representation both read it; neither adapter keeps a private match. Codes are flat `SCREAMING_SNAKE` strings whose names carry no parsed meaning.

**A code is a recovery unit, not a variant.** A new code is justified only when the recovery action differs; otherwise the difference belongs in typed details. `VALIDATION_ERROR` therefore covers field type mismatch, missing required field, unknown field, empty or multi-line title, bad status literal, `set`/`clear` conflict, and `null`; `CYCLE_DETECTED` covers dependency and parent cycles with the kind in details; `INVALID_RELATIONSHIP` covers self-reference, duplicate edges, and wrong relation kinds with the reason in details.

**Envelope.** Every error carries `{v, code, message, details, location?, retryable}`. Details are typed per code; location is a tagged union over `work_item`, `file`, `field`, `config_key`, and `relationship`. Messages stay human and are never parsed for classification. JSON-mode failures go to stdout as `{v, ok: false, error}`, so a parser always receives valid JSON; stderr stays narrative.

**Findings share the registry.** `{severity: error|warning|info, code, location?, message, fixable}`; `validate --strict` maps remaining error-severity findings to exit 3; doctor's held-lock probe is an info-level, non-fixable finding. Warnings ride in `_meta.warnings` as `{code, message, location}` and never change the exit code.

**Exit classes.** 1 is usage (adapter-level `USAGE_ERROR`, outside the registry); 2 not found; 3 invalid input or data; 4 conflict or state rejection (write conflict, archived item write, already archived, active children); 5 filesystem, Git, or environment, including lock contention and an unstable reader snapshot; 6 version or migration, including stale-generation write rejection; 7 internal. Only `LOCK_TIMEOUT` and `SNAPSHOT_UNSTABLE` are retryable; every other code is terminal.

**The frozen registry.** Class 2: `ITEM_NOT_FOUND {id, relation?}`, `CATEGORY_NOT_FOUND {key}`. Class 3: `VALIDATION_ERROR {target, issues:[{path, reason}]}`, `INVALID_ID {value, reason}`, `PARSE_ERROR {path, reason}`, `CONFIG_INVALID {path, issues[]}`, `DUPLICATE_ID {id, paths[]}`, `ID_PATH_MISMATCH {id, path, stem}`, `CYCLE_DETECTED {kind, cycle[]}`, `INVALID_RELATIONSHIP {relation, from, to, reason}`, `INCOMPLETE_PROJECTION {completeness, freshness, diagnostics[]}`. Class 4: `WRITE_CONFLICT {id, path, expected_fingerprint, actual_fingerprint}`, `ITEM_ARCHIVED {id, operation}`, `ALREADY_ARCHIVED {id}`, `HAS_ACTIVE_CHILDREN {id, children[]}`. Class 5: `PROJECT_NOT_FOUND {searched}`, `IO_ERROR {path, operation}`, `GIT_ERROR {operation, reason}`, `LOCK_TIMEOUT {lock_path, waited_ms}`, `LOCK_FAILED {lock_path, reason}`, `SNAPSHOT_UNSTABLE {retries}`. Class 6: `UNSUPPORTED_VERSION {found, supported}`, `ITEM_NEEDS_MIGRATION {id, item_generation, project_generation}`, `ACTION_REQUIRES_MIGRATION {action, required_command}`, `MIGRATION_PATH_CONFLICT {target, conflict}`, `MIGRATION_UNSUPPORTED_GENERATION {requested, supported}`, `MIGRATION_PRECONDITION_FAILED {diagnostics[]}`, `MIGRATION_FAILED {per_target:[{path, outcome, error?}]}`. Class 7: `ROLLBACK_FAILED {applied[], failed[], rollback_failed[]}`, `ID_GENERATION_FAILED {attempts}`, `INTERNAL_ERROR {}`. No exit class: `OWNER_MISMATCH` (warning), `LOCK_HELD` (info), `MIGRATION_AVAILABLE` (info), `NOT_A_GIT_REPOSITORY` (info), `DANGLING_REFERENCE` (error-severity finding), `TIMESTAMP_INCOHERENT` (warning finding).

**Pinning.** A wildcard-free compile-time match forces every error variant to declare a code; a registry-consistency test keeps the code table and that match in step; a JSON-schema enum round-trip keeps the documented schema honest; and a golden snapshot records each code's exit class, retryability, details keys, and location kinds. Changing any of them requires updating the snapshot and the documented table in the same change.
