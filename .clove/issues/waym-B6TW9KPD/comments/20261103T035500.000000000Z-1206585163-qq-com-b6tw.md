Resolution: `create` requires title, category, and owner; nothing is derived. Title is the single positional argument, category is required with no default category, and owner is required with no fallback to the configured operator.

`creator` is provenance only. It is optional, recorded at creation, and immutable afterwards; it carries no validation, authorization, workflow, or query semantics. An explicitly supplied value wins; the configured operator is used when the caller omits it; when neither exists the field stays unset. Losing the derivation is acceptable precisely because the field is only a trace.

Required custom fields must be satisfied at creation. If any declared `required` field is absent after static defaults are applied, the whole create fails and reports every missing field — Waymark never writes a work item that is immediately schema-invalid. Value precedence is explicit request value, then declared static default, then not written. Unset optional fields are omitted and never serialized as null; an explicitly supplied empty string or empty list counts as a supplied value, not as a missing one.

`create` may carry a body, custom-field values, and initial parent, dependencies, and soft links. A create without initial relations needs only a scoped read of configuration and schema. A create with initial relations requires a complete fresh projection, because existence, active state, self-reference, duplicate, and cycle checks are whole-graph questions. Any invalid initial relation fails the whole create.

Callers never supply `id`, `created_at`, or `updated_at`. CLI shape is `waymark create <title> --category <key> --owner <who> [--creator <who>] [--body <text> | --body-file <path>] [--field key=value]... [--parent <id>] [--depends-on <id>]... [--link <id>]...`. MCP exposes `waymark_create_work_item` with the same fields and returns the complete created work item, matching the edit operations' response shape.
