Resolution: Every work item has a required human owner; created_by is creator provenance. On create, the current configured operator may assign a different human owner; creator and owner need not match. All subsequent Waymark-mediated writes through the shared domain library (CLI, MCP, or future adapters) check configured operator == that item's owner; reads do not. The owner transfer operation itself must pass the current owner/operator check; once transferred, the new owner/operator takes over immediately, with no acceptance state. Batch writes are all-or-nothing: validate ownership, schema, references and concurrency for the full set before any write; any failure means no item changes. Executor remains project-defined custom-field data and grants no write authority. Configured operator/creator values are declared local identities, not authenticated identity or tamper-proof audit evidence; direct file edits or config changes can bypass the guardrail.
