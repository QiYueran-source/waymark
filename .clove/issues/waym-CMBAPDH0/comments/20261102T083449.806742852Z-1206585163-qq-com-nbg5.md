Resolution from the Wayfinder design session:

- Web is a strictly read-only, deliberately simple visual overview, not an AI-replacement search/filter interface.
- The primary presentation is a top-to-bottom tree of all non-archived items. Provide both one combined hierarchy and a category-grouped view; default to the combined tree and remember the last selected view. Categories remain project-defined groupings, not hierarchy. In grouped view, cross-category children stay nested beneath their parent; category identity is also distinguished by a stable assigned node shape (e.g. circle, square, pentagon, triangle) and category name/abbreviation. Shape assignments cycle stably when there are more categories than shapes.
- Every item, including items without a parent, appears as a tree root or descendant; do not invent a synthetic root node. Closed items remain visible and have their own color. Colors encode work state, not arbitrary/custom category status fields: open/ready, in-progress, blocked (derived only for non-closed items with unfinished hard dependencies), and closed. Blocked is not a writable status and cannot coexist with closed under the domain rule. Nodes also carry a concise blocked marker; details show specific unfinished dependencies.
- Solid tree edges represent parent-child hierarchy. Dependency edges are optional dashed lines controlled by a simple global show/hide button; remember this setting separately per view. Dependencies are not hierarchy. In grouped mode, if a displayed item depends on an item in another category, showing dependencies adds a reference node for the referenced item and a dashed edge to it. If that referenced item has a parent, use that parent as the cross-category connection point; if it has no parent, use the referenced item itself. When dependencies are hidden, neither these reference nodes nor dashed edges appear.
- Clicking an item name opens a read-only detail view with body, category, actual status, blocked reason, owner/executor and relationships.
- Keep tree browsing simple: expand/collapse individual nodes and offer Expand all / Collapse all. The latter expands all levels or collapses to roots. Keep expansion state separate for the two views.
- Persist selected view, each view’s expansion state, dependency visibility per view, and page scroll position in the current browser so browser refresh preserves context; do not write these preferences into project data. No in-page refresh button: users refresh through the browser.
- On small screens retain the vertical tree with compact indentation, wrapping and vertical scrolling. For empty projects show a concise empty state; if no categories are configured, the combined tree still works without category shapes. For invalid/missing parent references, show valid trees and put unattachable items in an explanatory unresolved-relations area rather than hiding all data or silently treating them as ordinary roots.
- Archived items are excluded from the default tree. Any separate archive-browsing UI remains undecided/outside this resolution.
