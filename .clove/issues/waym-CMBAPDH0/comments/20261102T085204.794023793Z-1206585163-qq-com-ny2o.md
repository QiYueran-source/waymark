Resolution (captured in the prior design discussion): Web is a strictly read-only, deliberately simple visual overview, not an AI-replacement search/filter interface. The primary presentation is a top-to-bottom tree of all non-archived items; provide combined and category-grouped views, default to combined, and remember the last selected view. Categories remain project-defined groupings, not hierarchy; in grouped view cross-category children stay nested under their parent, and category identity uses stable node shapes plus category name/abbreviation (shape assignments cycle stably if categories exceed available shapes). All items, including parentless items, appear without a synthetic root. Closed items remain visible. Color encodes open/ready, in-progress, derived blocked (only non-closed items with unfinished hard dependencies), or closed; blocked has a concise marker and details show the specific unfinished dependencies. Solid edges are parent-child; optional dashed dependency edges use a global show/hide control remembered separately per view. In grouped view, a visible dependency on another category adds a reference node and dashed edge; use the referenced item's parent as cross-category connection point when it has one, otherwise the referenced item itself. Hiding dependencies hides both edges and reference nodes. Clicking an item name opens read-only details (body, category, actual status, blocked reason, owner/executor, relationships). Support per-node expand/collapse plus Expand all/Collapse all, with expansion state separate per view. Persist selected view, per-view expansion and dependency visibility, and scroll position in the browser only; no project-data writes or in-page refresh button. Small screens retain a vertical tree with compact indentation, wrapping, and vertical scrolling. Show a concise empty state; combined view works without categories/shapes. Invalid/missing parent references do not hide valid trees: show unattachable items in an explanatory unresolved-relations area. Archived items are excluded from this default view; separate archive browsing remains undecided. No additional Web interaction/design question was raised in the design discussion.
