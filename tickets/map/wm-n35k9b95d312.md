## Question

Which supported DSH plugin APIs can register a right-sidebar page, identify the active session workspace, communicate with a host component, and manage per-project resources and plugin lifecycle? Establish installation, version and test constraints from the installed implementation and official documentation; distinguish verified behavior from assumptions.

## Research context

Local research branch: `research/dsh-sidebar`. Findings are being prepared at `docs/research/dsh-sidebar.md` on that branch; they are not merged or pushed.

## Resolution

Verified against the installed DSH `0.2.1-rc.5` on 2026-11-04, from first-party package declarations and shipped implementation. Source contracts only: no plugin was installed, no profile changed, and no server started.

- **Right-sidebar page:** a client plugin registers a static tab with `ctx.sidebarRightTabs.register(definition)`, which returns an idempotent disposer; the body registers under the session-scoped keyed slot `sidebar.right.pane.tab` with `key: definition.id`, and `ctx.effect` owns cleanup. The tab is session-scoped and restores layout per session.
- **Session workspace:** slot props carry `sessionId`; the shipped Files tab reads the original workspace root with `useSessions((sessions) => sessions.byId[sessionId]?.cwd)`. `cwd` is the session's creation workspace and may be missing. It is not the mutable working directory (`useProjection('workingDirectory')`) and not `process.cwd()`. `workspaceFiles` is read-only and is not a project-write API.
- **Host communication:** client `ctx.remote` exposes generated, assembly-selected namespaces over the authenticated gateway; handle missing injection, aborts and remote failures. Whether an independently packaged plugin can generate, distribute and activate its own Remote descriptors with the installed tooling is **not established**.
- **Resources and lifecycle:** `ctx.resources.register` is a UI resource stream, not a filesystem write service. A tab's `signal` aborts on record removal or plugin unload, not on hide or session switch; `keepMounted` defaults to false, so tie subscriptions and processes to their real owner.
- **Packaging:** a bundle declares `dsh.bundle.patch`; a UI bundle exports `./client` and declares `dsh.client`; install through `plugin_manager` `install_bundle`, not manual profile edits. Compatibility preflight uses an explicit `engines.dsh` range or matching `@deepseek-ai/dsh*` peers; prereleases count, and there is no stable cross-release API/ABI guarantee.

**Not established:** a third-party Remote build recipe, live availability of the required services in this profile, and end-to-end behaviour. Live inspection and an integration test remain prerequisites before a design commitment.
