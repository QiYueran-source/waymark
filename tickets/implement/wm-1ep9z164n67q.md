## What to build

The read-only Web view shows timestamps in the viewer's own zone, because it reads the same effective configuration the CLI and MCP read.

The view resolves the effective time zone through the shared core boundary and never parses the local document itself. Two collaborators looking at the same project through the same checkout see the zone that machine resolved, and neither sees the other's preferences.

## Acceptance criteria

- [ ] The Web view uses the effective time zone from the shared core boundary and renders display timestamps in it.
- [ ] The Web adapter contains no independent parsing of the local document and no copied precedence rule.
- [ ] A project with no local document still renders using the resolved fallback zone.
- [ ] Web tests assert the resolved zone and that the adapter delegates to the shared boundary.
