## What to build

Make the by-category tree answerable to a reader instead of showing every category at once. The by-category view gains a category selection control built from the project's configured categories, showing each category's stable shape and name. Selection is multi-select and offers select-all and clear-all.

Only work items in selected categories remain. The selection is remembered per project in browser storage alongside the existing view preferences.

## Acceptance criteria

- [ ] the by-category tree shows one selection control per configured category, including categories with no active work items
- [ ] each option carries the category's stable shape and name, so the control matches the tree's existing category cues
- [ ] several categories can be selected at once, and the tree then shows work items from all of them
- [ ] select-all restores every configured category and clear-all leaves none selected
- [ ] the selection persists per project and survives a reload; a different project on the same origin does not inherit it
- [ ] the combined view is unchanged by this control
- [ ] with browser storage unavailable the control still filters for the session and the existing persistence notice appears
- [ ] frontend tests cover single selection, multi-selection, select-all, clear-all, persistence, per-project isolation, and unavailable storage
