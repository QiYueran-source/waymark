## What to build

Decide which client-side library renders the read-only work graph, and pin it so the rest of the graph work can rely on it. The comparison is judged only against this project's contract: strictly read-only, a fixed top-to-bottom hierarchical layout, solid parent-child edges, optional dashed directed dependency edges, non-draggable nodes, semantic node labels the app controls, and a seam the existing frontend test suite can drive without asserting library internals.

Evaluate Cytoscape.js and Svelte Flow at minimum. Record the decision and its reasons in the implementation decisions document, then add the chosen library and its pinned version to the frontend lockfile.

No product-facing behaviour ships in this ticket; the Web view is unchanged when it is done.

## Acceptance criteria

- [ ] the two candidate libraries are compared against read-only suitability, hierarchical layout, dashed and directed edges, custom node content, accessibility surface, testability, bundle weight, and maintenance status
- [ ] the decision and its rejected alternative are recorded as an implementation decision, not only in a commit message
- [ ] the chosen library and an exact pinned version are in the frontend lockfile and resolve from the lockfile alone
- [ ] the frontend still builds, checks, and tests green with the dependency present but unused
- [ ] no library is imported anywhere in application code yet, and no second rendering stack is introduced
- [ ] the integration seam is described: which module owns the graph model and which owns library-specific rendering

## Blocked by

None (can start immediately).
